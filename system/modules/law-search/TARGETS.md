# 국가법령정보 DRF — target 표

전사 원본 = 법제처 OPEN API 가이드(2026-08-13 사용자 제공분). **여기 없는 건 안 적은 것이지
없는 게 아니다** — 문서를 받은 target 만 있다.

두 엔드포인트뿐이고 모든 target 이 같은 모양을 쓴다:

- 목록 `lawSearch.do?target=X` — 공통 가족 `query · display(≤100) · page · sort · gana · popYn`
- 본문 `lawService.do?target=X` — `ID | MST` 중 하나 필수, + `LM · LD · LN`, 일부 `JO`

아래 표의 "고유"는 그 target 에만 있는 것. `구현` = 우리 모듈이 현재 다루는가.

## 위원회 결정문 — 한 가족, 한 모양

뿐이고, 본문은 **`ID`(결정문 일련번호) 하나만** 받는다. MST 도 LM 도 없다.

위원회 계열은 전부 https 로 문서화돼 있다(법령 계열은 http). 같은 호스트라 스킴만 맞추면 된다.

💡 **`fields`(nhrck 전용)** — 응답에 실을 항목을 이름으로 고른다(HTML 출력엔 미적용). 벤더가
제공하는 열 선택이라, 목록을 통째로 받아 캐시에 넣고 나중에 줄이는 것보다 **애초에 적게 받는** 쪽이
싸다. 우리가 시트에 만든 `rowsColumns` 와 같은 발상이고, 표 리팩터 때 "이 target 은 열 선택을
지원한다"를 선언에 담을 자리다. 다른 target 에는 없다.

본문에서 특히 값한다: nhrck 결정문은 `결정례전문`(문서 통째)을 한 필드로 주는데, `fields` 로
`결정요지`·`주문요지` 만 고르면 **전문을 컨텍스트에 들이지 않고** 답할 수 있다. 전문이 필요하면
`원본다운로드URL`·`바로보기URL` 로 사람에게 넘긴다.

⚠️ **`문서제공구분`** — `kcc`·`iaciac` 본문에 있고 값이 "데이터 개방 | **이유하단 이미지개방**"
이다. 후자면 `이유` 가 비어 온다: 텍스트가 없는 게 아니라 **이미지로만 공개된 건**이다. detail 의
`found:false` 가드가 이걸 "빈 본문"과 같게 취급하면 오진이 되므로, 붙일 때 그 필드를 읽어
"본문이 이미지라 텍스트가 없다"를 따로 말하게 할 것.

  그대로 사용자에게 넘어간다. 링크를 답변에 그냥 적으면 외부 URL 이라 카드가 안 선다.

## 학칙·공단·공공기관 — 한 문서, 세 target

`school`(대학) · `public`(지방공사공단) · `pi`(공공기관). 파라미터도 응답도 동일하고, **응답
필드 이름이 `행정규칙*` 을 그대로 쓴다**(행정규칙일련번호 = 학칙공단 일련번호). 즉 admrul 파서를
그대로 재사용할 수 있고, 다른 점은 `knd`(1학칙/2학교규정/3학교지침/4학교시행세칙/5공단·공공기관규정)와
`rrClsCd`(**200401~200410** — 법령의 3002xx 와 완전히 다른 코드계)뿐이다. 본문도 admrul 과 같은
규칙: **`ID`=일련번호 / `LID`=학칙공단ID** + `LM`.

0건이고 짧은 질의는 노이즈다(2026-08-13 실측). `lstrmRlt` 의 **상위어/하위어/동의어**는 그 질의를
**추측이 아니라 사전으로** 넓히고 좁히는 수단이고, `dlytrm` 은 사용자가 쓴 일상어("바람피움")를
법령용어("부정행위")로 옮기는 입구다. 모델이 동의어를 지어내지 않아도 되는 유일한 경로.

⭐⭐⭐ **`aiSearch` 가 1순위.** 개념어 한 마디로 **조문 본문**이 온다("뺑소니" → 관련 조문). 우리가
오늘 `search:"2"`(본문검색) 안내로 우회한 문제를, 법제처가 별도 엔드포인트로 이미 풀어 놓았다.
lawSearch 계열의 AND 매칭·제목검색 한계가 여기엔 없다.

⭐⭐ **`lstrmRltJo` = 오늘 실패한 턴의 정답(2순위).** 용어 하나(`query`)로 그 말이 쓰인 **조문 본문**이
바로 온다 — 검색도, id 도, 페이징도 없이. turn 58 은 "혼인을 계속하기 어려운 중대한 사유"에서
민법 제840조로 가지 못해 1,337 조문을 손으로 넘기다 예산을 태웠는데, 그 경로가 이 한 호출이다.
`dlytrmRlt`(일상어→법령용어, 응답에 조문 링크 동봉)와 이으면 **"바람피움" → "부정행위" → 제840조**
가 두 홉이다. 붙이는 순서 = **`aiSearch` → `lstrmRltJo` → `dlytrmRlt`·`lstrmRlt` → 나머지.**

**`lstrm` 본문 조회가 `ID` 가 아니라 `query`(용어명) 하나다** — 이 API 전체에서 유일하게 목록을 먼저
거치지 않아도 되는 target. 용어 하나 확인 = 호출 하나.

법률 질의에서 값하는 자리다 — "부정행위"·"중대한 사유" 같은 말의 **정의**를 조문 본문을 뒤지지
않고 바로 집을 수 있다. 오늘 turn 58 이 1,337 조문을 페이징한 것과 정반대의 비용이다.

## 이름이 겹치는데 뜻이 다른 것 (사고 지점)

- **`JO`** — 법령 본문에선 **조번호 6자리 = 조번호(4) + 조가지번호(2), 왼쪽 정렬**
  (제840조 = `084000`. 오른쪽 정렬로 읽어 `008400` 을 쓰면 제84조가 나온다 — 2026-08-13 실측).
  그런데 **`prec` 검색에선 참조법령명 문자열**("민법")이고, **`lnkLsOrdJo` 에선 4자리**다.
- **`ID` / `MST`** — 법령은 `ID`=법령ID, `MST`=법령일련번호. **admrul 은 반대**(`ID`=일련번호,
  `LID`=행정규칙ID), **ordin 은 `ID`=자치법규ID, `MST`=일련번호**. 검색 행에 둘이 나란히 오므로
  섞어 쓰면 "일치하는 법령이 없습니다" 가 돌아온다.
- **`knd`** — 대개 종류 코드인데 **`lnkLsOrd` 에서는 법령ID**, **`thdCmp` 에서는 1/2 비교유형**이다.
- **`nw`** — law/eflaw 는 1연혁·2예정·3현행, **admrul·ordin·school/public/pi 는 1현행·2연혁**으로
  뒤집혀 있다.
- **`rrClsCd`** — 법령·자치법규는 `3002xx`, **학칙공단 계열은 `2004xx`** 로 코드계가 통째로 다르다.
- **`knd`** — 별표종류마저 갈린다: licbyl 은 3별지/4별도, **ordinbyl 은 3별도/4별지**로 뒤집혀 있다.

## 리팩터 메모

target 별 `if` 분기가 아니라 이 표를 데이터로 두면, 새 target 은 한 줄이고 `target` enum·설명·
ID 필드명·검증이 전부 한 곳에서 파생된다. 응답 파싱은 제네릭 + raw 폴백을 유지하고, 각 target
첫 실호출에서 루트 키를 확정한다(문서가 명세하는 건 요청 모양이라 요청 조립은 지금도 검증 가능).
